# 데이터 결손 감시 — 컨텍스트 노트

작업일 2026-08-14. 결정과 근거만 남긴다. 다음 세션이 다시 도출하지 않도록.

## 왜 새 봇이 아니라 Vercel cron 인가

mac-mini/Vultr 봇으로 만들면 워커 배포·launchd 등록·사본 이중화 관리가 따라온다. 이 점검은 DB 쿼리 몇 개 + 캐시된 경력 조회라 Vercel cron 으로 충분하다. `/api/internal/content-quality` 에 얹는 것도 검토했지만 그쪽은 15분 주기라 af 캐시 조회를 태우기엔 과하다.

## 왜 하루 2회인가

경력 캐시 TTL 이 24시간이라 사고가 하루 주기로 생겼다 사라졌다 한다. 하루 1회면 회복된 시점만 볼 수 있다. 12시간 간격이면 최소 한 번은 사고 상태를 본다. af 콜은 캐시 히트라 거의 0 이다.

## 왜 개별이 아니라 비율 판정인가

선수 한 명이 현 시즌 무출전인 건 정상이다 — 실제로 표본에 무드리크(도핑 정지)가 들어오면 af 에 2026 데이터 자체가 없다. 개별 판정은 이런 정상 케이스마다 울린다. 파이프라인이 고장나면 표본 전체가 같이 뒤처지므로 비율이 정확한 신호다.

## 임계는 실측 위에 세웠다

처음 40% 로 잡았다가 25% 로 내렸다. 사고 당시 실측이 42%(5/12)라 40% 는 겨우 스치는 값이었다. 정상은 0% 이므로 25% 로 내려도 정상과 충분히 떨어진다. `CAREER_ALERT_MIN = 3` 을 같이 둬서 표본에 정상 stale 이 한둘 섞여도 안 울린다.

## 오탐의 정체 — 비수기와 컵대회

첫 실측에서 UEL·UECL·UCL·AFC_CL_TWO 가 1,370시간대 정체로 잡혔다. 전부 정상이다(유럽컵 예선 기간이라 조별 순위가 안 움직인다). 리그 리더보드도 AFC_CL_TWO 45일·LOL 63일이 잡혔는데 같은 이유다. 그래서

- 활성 리그 게이트(최근 14일 종료 매치)
- 컵/대륙대회 정규식 제외

두 개를 넣었더니 정체가 1건(J3_LEAGUE 142h)만 남았다. 이건 진짜 신호일 수 있어 임계(72h·3건 또는 168h 1건) 안에 들어오게 뒀다 — 7일을 넘기면 울린다.

리그 리더보드 축은 이번에 넣지 않았다. LOL 같은 이스포츠·컵 리그 예외가 많아 규칙이 복잡해지는데, 리더보드 결손은 사용자 피해가 상대적으로 작다.

## 로컬에서 검증할 때 함정

`getPlayerCareerByTs` 를 tsx 스크립트로 직접 부르면 `unstable_cache` 가 Next 런타임 밖이라 **전원 빈 결과**가 나온다(12/12 stale). 이걸 사고로 오해했다가 dev 서버로 라우트를 호출해보고 0/12 인 걸 확인했다. 감시 로직 검증은 반드시 dev 서버 라우트로 한다.
