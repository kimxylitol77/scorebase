# `/news` 해외 뉴스 게시판 — 컨텍스트 노트

작업 시작 2026-08-19. 선행 작업 `docs/news-briefing/` (2026-07-04 파이프라인 구축) 참조.

## 결정과 근거

### 새로 만들지 않고 기존 파이프라인을 확장한다
사용자 요청은 "게시판 형식 뉴스 페이지 신설"이었으나, 실측 결과 파이프라인은 이미 있고
정상 가동 중이었다(누적 478건, 당일 14:20 발행 확인). 없는 건 파이프라인이 아니라
**독립된 노출 경로**와 **종목 커버리지**였다. 그래서 수집·재작성·검증은 그대로 두고
소스·배분·프론트만 손댄다.

### "번역"이 아니라 "사실 재구성"을 유지한다
사용자 표현은 "해외 뉴스를 한글로 번역"이었지만, 전문 번역은 출처를 표기해도
2차적저작물작성권 침해다(번역요약물 대법원 판례). 기존 코드가 이미 이 원칙으로 고정돼 있고
(`REWRITE_SYSTEM` 1~3번 규칙 + 검증 게이트 2번), 그대로 유지한다. 사용자에게 이 점을
명시적으로 보고했다. 결과물의 독자 체감은 번역 기사와 유사하되 법적으로 안전하다.

### 블랙리스트를 화이트리스트로 뒤집는다
사용자가 "공신력 있는 곳만"을 명시 요구했다. 기존 방어는 `TABLOID_RE` 블랙리스트뿐인데,
블랙리스트는 원리적으로 새어나간다. 실측 발행 소스 분포에서 이미 확인됐다 —
`MSN 25 · TheHardTackle 7 · Motorcycle Sports 6 · The Real Champs 5`.
gnews 기자 피드가 제목 끝 매체명을 `promote` 로 승격시키는 경로가 구멍이었다.
화이트리스트 밖이면 승격 대신 **항목 폐기**로 간다. 소스 기본명으로 폴백하지 않는 이유는
오귀속(다른 매체 기사를 BBC 것으로 표기) 방지.

### 종목은 소스가 고정하고 LLM 분류에 맡기지 않는다
LLM 이 종목을 오분류하면 야구 뉴스가 축구 게시판에 꽂힌다. RSS 소스는 이미 종목별로
분리돼 있으므로 `SourceDef.sport` 로 고정하는 게 정확하고 비용도 0.

### 종목별 런 상한을 둔다 (일일 캡 단순 상향이 아니라)
최근 10일 발행량이 8~12건으로 일일 캡 12에 거의 포화. 즉 축구 재료만으로 캡이 찬다.
score 단일 정렬을 유지하면 종목을 늘려도 축구가 전부 먹는다. 그래서 종목별 런 상한
(축구 2 · 타 종목 각 1)을 둔다. 단 `MIN_SCORE=5` 게이트는 유지하므로 비시즌으로 재료가
없는 종목은 억지로 채우지 않고 그냥 비운다 — 쿼터 채우기용 저품질 발행 방지.

### 개별 글 URL 은 옮기지 않는다
브리핑 478건이 `/analysis/{id}` 로 이미 색인돼 있다. `/news/{id}` 로 옮기면 색인 손실과
중복 URL 이 동시에 생긴다. 목록 페이지만 신설하고 상세는 기존 경로를 쓴다.
대신 `/analysis?board=briefing` 은 `/news` 로 308 — 같은 목록이 두 URL 로 존재하면
카니발라이제이션이 난다.

## 함정 (선행 작업에서 계승)

- `prisma db push` 금지 — prod DDL 은 raw SQL + `lock_timeout 3s` (락 사고 이력).
- gnews link 는 2024+ 신형 인코딩이라 원 URL 복원이 자주 실패 → 헤드라인 기반 짧은 브리핑.
  재료 부족분은 검증 게이트가 알아서 막는다.
- `verify` 프롬프트에 소스명을 안 넣으면 정당한 출처 표기를 날조로 오판한다.
- haiku 분류 점수는 런간 변동이 크다 → `keep` 무시하고 score 게이트 + storyKey 48h 중복 방지.
- 워크트리에서 DB 스크립트를 돌리려면 `.env.local` 심링크가 필요하다 (이번에도 걸렸다).
- `Post` 모델에 `hidden` 필드는 없다. 숨김은 `NewsBriefing.status='HIDDEN'` 쪽이다.

## 작업 중 발견 — 과거 발행분 39%가 비공신력 매체 (2026-08-19)

새 화이트리스트는 앞으로 발행될 글만 막는다. 이미 발행된 478건을 실측하니 **186건(39%)**이
화이트리스트 밖이었다. `MSN 25 · Football365 21 · OneFootball 7 · Motorcycle Sports 6` 에다
팬블로그(Arseblog · Spurs Web · DaveOCKOP · The Empire of The Kop 등) 다수, 그리고
`Crypto Briefing` · `Rugby Addict` · `SSBCrack` 처럼 해당 종목 매체조차 아닌 것까지 섞여 있었다.

/news 가 "공신력 있는 해외 보도만"이라고 약속하는데 목록 39%가 그렇지 않으면 그 문구가
사실이 아니게 된다. 사용자 선택으로 **목록에서만 숨김**.

- `Post.category` 를 `BRIEFING` → `BRIEFING_LEGACY` 로 변경 (`scripts/hide-nonwhitelist-briefings.mjs`).
  글 URL `/analysis/{id}` 과 색인은 그대로 살아 있고, `REVERT=1` 로 한 번에 되돌릴 수 있다.
- **함정** — `/analysis/[id]` 는 `category: { in: [...] }` 화이트리스트로 글을 조회한다.
  여기에 `BRIEFING_LEGACY` 를 안 넣으면 숨긴 글이 전부 404 가 되어, 색인 보존이라는 이 방식의
  근거 자체가 무너진다. `board-move.ts` 의 이동 금지 판정도 같이 `startsWith("BRIEFING")` 로 바꿨다.
- 결과: 목록 292건, 숨긴 글 상세 URL 200 확인.

## 작업 중 발견 — 종목을 늘려도 축구가 분류 상한을 독식했다

첫 DRY 에서 야구·농구 후보가 0건이었다. score 게이트 문제가 아니라 **분류 단계 이전**이 원인.
축구 소스가 8개 피드(BBC 72건 + gnews 100건씩 6개)라, 신규 788건을 최신순 40건으로 자르면
그 40건이 전부 축구였다. 타 종목은 LLM 분류를 받아보지도 못했다.

→ `NEW_PER_SPORT` 종목별 분류 쿼터(축구 20 · 나머지 각 8). 적용 후 `basketball:8 soccer:20
hockey:8 baseball:8` 로 4개 종목 전부 분류 단계에 도달했고, 하키 첫 브리핑이 실제로 나왔다.

교훈: "왜 안 잡히나"를 게이트 임계값부터 의심하면 틀린다. 파이프라인 상류의 자르기가
표본을 이미 편향시켰는지 먼저 본다.

## 화이트리스트는 실측으로 무는 걸 확인했다

DRY 로그에 `비공신력 소스 차단 162건`. 필터가 실제로 동작하는지 로그로 남기지 않으면
"설정했으니 되겠지"로 끝난다 — 카운터를 런 로그에 넣은 이유다.

## 현재 종목별 발행 전망 (사용자 안내용)

8월 시점 야구·농구·하키 발행량은 낮다. NBA·NHL 은 비시즌이고, MLB 는 시즌 중이지만 뉴스가
대부분 단일 경기 결과·개인 기록이라 rubric 상 score 5 미만이다. 이건 설계대로다 —
쿼터를 채우려고 가치 낮은 기사를 올리지 않는다. NBA·NHL 개막(10월)과 MLB 포스트시즌(9~10월),
FA·트레이드 시즌에 자연히 올라온다.
