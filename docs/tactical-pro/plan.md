# 전술 분석·이달의 감독 — 전문가 수준으로 (계획)

작성 2026-09-28.

## 무엇을

EPL 경기 전술 분석 글과 이달의 감독 글을, 해외 전술 채널(Tifo Football 류)이 쓰는 구성과 도식으로 끌어올린다.
글 안에 전술 이미지(형태 도식·경기 흐름·골 장면 패스 경로·스타일 비교)를 넣는다.

## 왜

지금 전술 글은 라인업을 문장으로 풀고 경고·교체 시각을 나열하는 수준이다(2026-09-28 K리그1 글 실독).
원인은 모델이 아니라 재료다. DB 에 있는 경기 흐름·골 빌드업 좌표·팀 통계 40여 종·선수 스탯을 프롬프트가 하나도 안 쓴다.

## 확정 결정 (사용자 답변 2026-09-28)

1. 참고는 해외 전술 채널. 내용이 아니라 구성·시각화 방식만 참고한다.
2. EPL 먼저. 데이터가 가장 풍부하다.
3. 초안(DRAFT)으로 저장하고 검토 후 발행.
4. 이달의 감독은 데이터로 자동 선정. 선정 근거를 글에 공개한다.

## 구성 (해외 전술 채널 형식을 글로 옮김)

| 순서 | 섹션 | 근거 데이터 | 도식 |
|---|---|---|---|
| 1 | 한 문장 명제 (이 경기를 가른 것) | 전체 | |
| 2 | 두 팀의 설계 | 포메이션·선발 | 형태 겹침 도식 (기존) |
| 3 | 공을 가졌을 때 | 패스·롱볼·크로스·박스 안 슈팅·빅찬스 | 스타일 비교 막대 |
| 4 | 공을 잃었을 때 | 태클·가로채기·클리어·경합·파울 | |
| 5 | 흐름이 바뀐 지점 | 분당 모멘텀·전후반 통계·교체 | 경기 흐름 그래프 |
| 6 | 골의 해부 | 골 빌드업 패스 좌표 | 골 장면 패스 경로 |
| 7 | 숫자가 가리킨 선수 | 선수 스탯 | |
| 8 | 결론과 다음 경기 | | |

## 구조

| 층 | 내용 |
|---|---|
| 지표 계산 | `src/lib/tactical/insights.ts` 순수 함수 + 단위 테스트. 해석에 쓸 숫자는 코드가 만들고 모델은 서술만 |
| 프롬프트 | `src/prompts/tactical-analysis.ts` 에 `pro` 구성 추가. 재료가 있는 경기만 |
| 도식 | `src/components/tactical/*` 서버 SVG 컴포넌트. 본문 토큰 `{{tactical-…}}` 자리에 렌더 |
| 초안 검토 | 관리자 로그인 상태면 DRAFT 글도 열림 (noindex) |
| 이달의 감독 | 선정식을 기대 대비 성과로. EPL 9월분 초안 1편 |

## 검증

1. 지표 계산 → 검증: 단위 테스트 + 실제 EPL 경기 1건의 값이 원자료와 맞는지.
2. 도식 → 검증: 로컬 렌더, 375px, 라이트·다크.
3. 글 → 검증: dry-run 으로 본문 확인, 팩트 게이트 통과, 초안 저장 후 관리자 미리보기.
4. 마무리 → 검증: typecheck, 전체 테스트.
