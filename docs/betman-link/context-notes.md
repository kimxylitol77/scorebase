## 결정
1. 매핑은 새 이름 매칭을 만들지 않고 **기존 TEAM_MAP + 킥오프 ±3h** 그대로 배치로 돌린다(빌더가 이미 경기 대조로 만든 사전). (gmTs, matchSeq) 단위로 같은 경기의 전 베팅유형 행에 같은 matchId 를 쓴다. 홈·원정 뒤집힌 매칭은 받지 않는다(개최지 이전 스왑 사고 메모리).
2. 크론은 Vercel(`/api/cron/betman-link`) — 워커가 00·12 UTC 에 적재하므로 01·13 UTC. 종료 경기도 대상(아카이브용). CRON_REGISTRY 등록(감시봇 공백 메모리).
3. 카드의 마진은 `sum(1/odds) − 1`. 해외는 `Match.oddsHome/Draw/Away`(vig 미제거 평균)라 같은 식으로 비교 가능. 야구는 2-way 라 무 제외.
4. 배당 구간은 **인기픽(최저 배당) 기준**. 3-way 는 세 결과 중 최저. 정배당의 "낮은 배당 쪽 적중률 NBA 67.5%~K리그1 44.2%" 와 같은 정의라 숫자 비교가 된다.

## 구현 중 발견 (2026-09-11)
- **베트맨 카드는 축구 분기에만 배선돼 있었다.** `getBetmanLineForMatch` 의 `itemCode:"SC"` 고정은 증상이고, 진짜 원인은 상세 페이지가 `soccerOddsSection` 에서만 카드를 그린 것. 야구는 `MatchInsight.liveOddsContent`(라이브 배당 탭)에 카드를 얹어 해결. 야구 카드는 탭 안이라 SSR HTML 에 없고 탭을 눌러야 보인다 — curl 검증이 아니라 브라우저 클릭으로 확인할 것.
- **`matchSeq` 는 경기가 아니라 베팅 라인 단위.** id `{gmTs}-{matchSeq}` 가 PK 이고 승무패·핸디·언더오버가 각각 번호를 갖는다(정배당이 "#745-749" 범위로 보여주는 이유). 카드·패널의 #N 은 기본형(승무패/승패) 라인 번호. 실측 정배당 #745 = 우리 #745 (컵스-파이리츠) 일치.
- **연결 배치는 VALUES 조인 일괄 UPDATE.** 행 단위 updateMany 는 Neon 왕복 0.5s × 8천 = 1시간이라 Vercel 120s 를 넘긴다. 일괄로 9초. 첫 실행 결과 야구 99%·축구 77%·농구/배구 0%(사전 없음, 국대 "한국_여자"류) → 1,356경기 연결, 해외 배당 동반 1,223, 채점 1,036.
- 마진 실측(카드): 컵스-파이리츠 베트맨 13.7% vs 해외 4.7%(9.0%p), AZ-빌럼 14.9% vs 6.3%(8.6%p). 정배당이 같은 경기에 표시한 13.5% 와 0.2%p 차 — 발매 시점 차이.
- `/odds` 좌우 여백 문의 — 실측 1600px 에서 /odds 컨테이너 1440px(여백 100px), /scores 축구 max-w-7xl 1280px(여백 160px). /odds 가 사이트에서 가장 넓다. 여백이 큰 게 아니라 표가 넓게 펼쳐져 성겨 보이는 것. 변경 안 함.
