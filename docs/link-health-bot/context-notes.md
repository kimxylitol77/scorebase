# 링크 건전성 감시 봇 — 컨텍스트 노트

## 왜 만드나

2026-08-01, 사용자가 `/predictions/K_LEAGUE_1` 의 시즌 리더보드 선수 행이 클릭이 안 된다고
직접 발견했다. 감시봇 38종 중 아무도 못 잡았다.

원인은 감시의 사각지대다.

- `route-guardian` (24h) 은 sitemap + 내부 링크 BFS 로 **깨진 링크(404/5xx)** 를 찾는다.
  링크가 있어야 따라가므로, **아예 링크가 없는 행**은 구조상 안 보인다.
- `synthetic-monitor` (1h) 는 "있어야 할 마커가 있나" 를 본다. 선수 이름은 정상 출력되고
  있었으므로 통과한다.
- `content-quality` (15m) 는 "잘못된 값이 나가나" 를 본다. 링크 유무는 대상이 아니다.

즉 "표시는 멀쩡한데 눌리지 않는다" 는 유형은 사람만 발견할 수 있었다. 이 봇이 그 칸을 채운다.

## 무엇을 감시하나 (사용자 선택 4종)

| 종류 | 신호 | 판정 근거 |
|---|---|---|
| 선수 링크 누락 | 리더보드 행 중 `externalId == null` 비율 | 페이지와 **같은 함수**(`loadLeagueLeaderboard`)를 호출 |
| 팀 링크 누락 | standings 원본 행 대비 `Team.id` 해석 실패 | 해석 실패 행은 화면에서 사라지거나 링크 없는 텍스트가 됨 |
| 링크는 있는데 404 | `/transfers` 대상 ts id 가 `TheSportsPlayer` 에 부재 | `/transfers/[id]` 는 이 행이 없으면 `notFound()` |
| 팀 로고 누락 | standings 등장 팀의 `Team.logoUrl == null` 비율 | `TeamBadge` 는 로고 없으면 아무것도 안 그림(조용한 결손) |

## 핵심 설계 결정

### 0. 왜 새 봇을 안 만드나

처음엔 `mac-mini-worker/link-health.js` + `/api/internal/link-health` 조합을 계획했다.
착수 직전에 `src/lib/health-checks/` 를 발견하고 접었다.

이미 있는 것.

- 매일 06:30 KST Vercel cron 이 체크 함수 18개를 직렬 실행
- 결과를 `HealthCheck` DB row 로 적재, HIGH 는 텔레그램 자동 발송, `/admin/health` 에 표시
- `checkPlayerNameMissingRate` · `checkTeamNameMissingRate` 등 **거의 같은 모양의 이웃 체크**가 이미 존재

여기 함수 하나를 얹으면 봇 프로세스·launchd plist·`BOT_REGISTRY` 등록·맥미니 배포가 전부
불필요하다. 감시 대상 하나 늘리자고 감시 인프라를 하나 더 만들 이유가 없다.

### 1. HTML 파싱이 아니라 데이터 레이어에서 판정

처음엔 봇이 페이지 HTML 을 긁어 `<a>` 개수를 세는 안을 생각했다. 버렸다.

- 마크업이 바뀌면 조용히 오탐/미탐이 된다. 감시봇이 감시 대상보다 잘 깨지면 안 된다.
- Next.js 는 RSC payload 를 inline 하므로 문자열 매칭이 신뢰할 수 없다.
  (`route-guardian` 이 soft 404 검출을 포기한 것과 같은 이유 — 그 파일 주석 참고.)

대신 서버 라우트가 **페이지가 쓰는 바로 그 함수**를 호출해 판정한다. 링크 규칙이 바뀌면
판정도 자동으로 따라간다. 드리프트가 원천적으로 불가능하다.

### 2. 404 검사만 실제 HTTP 를 쓴다

`/players` af 폴백은 api-football 응답에 달려 있어 DB 만으로는 알 수 없다. 이건 봇이
표본으로 실제 요청을 보낸다. 전수는 낭비라 리그별 상한을 둔다.

### 3. 임계는 "비율" 이 아니라 "리그별 절대 건수 + 비율" 둘 다

비율만 보면 표본이 작은 리그(J2 8행)에서 1건이 12.5% 로 튀어 매일 운다.
절대 건수 하한을 같이 둬서 노이즈를 막는다.

### 4. 오프시즌은 정상이다

리더보드가 통째로 비는 건 비시즌이면 정상이다. **행이 0개면 검사 대상에서 제외**한다.
`league-leaders-resilience` 메모리의 "오프시즌 빈 결과 정상" 원칙과 같다.

  봇의 최초 알림에 그대로 잡힐 예정 — 오탐이 아니다.

## 철회한 검사 — team_link_missing

"최근 뛴 팀인데 순위표에 없어 순위표에서 팀 페이지로 못 간다" 를 넣었다가 뺐다.

2026-08-01 실측에서 9개 리그가 걸렸는데, 미등재 팀을 하나씩 까 보니 대부분 **예정 경기 0**
이었다. 지난 시즌을 끝내고 그 리그에 더는 없는 팀(강등·그룹 종료)을 60일 창이 "최근 활성"
으로 끌어온 것이다. 8월 1일은 유럽 새 시즌 개막 직전 = 이 오탐이 가장 심한 시점이다.

기준을 "예정 경기 ≥ 1" 로 좁혀도 시즌 전환기에는 순위표 자체가 지난 시즌 것이라 흔들린다.
게다가 비용이 컸다 — 순위표 122개 리그 조회에 **89.7초**, health-check cron 예산 90초를
혼자 다 쓴다. 얻는 신호는 standings 커버리지인데 그건 기존 감시가 이미 본다.

시즌 경계마다 우는 지표는 감시가 아니라 소음이다.

## 알아낸 것 — 기준선이 없으면 감시가 죽는다

최초 실행에서 18개 리그가 걸렸다. 전부 진짜다. 그런데 매일 HIGH 18건을 보내면
사용자가 알림을 끄고, 그러면 정작 새로 끊겼을 때 못 본다. `bot-monitoring-gap` 에서
이미 겪은 실패(경고 100%가 노이즈, 실제 탐지 0건)와 같은 구조다.

그래서 기존 결손은 LOW 로 적재만 하고, **기준선에 없던 키가 새로 뜰 때만** HIGH/MED 로
올린다. 최초 실행은 이력이 없으므로 전부 기준선으로만 잡는다 — 소급 알림은 의미가 없다.

## 회귀 테스트를 꼭 돌려라

처음 만든 체크는 `externalId` 유무만 봤다. 현재 상태에서 0건이 나와 "깨끗하다" 고 볼 뻔했다.
`league-leaderboard.ts` 를 수정 전으로 되돌려 재실행해 보니 **여전히 0건** — 원래 K리그
사건은 id 가 있는데 링크가 안 걸린 경우였고, 그 체크로는 영원히 못 잡는 것이었다.

판정을 화면과 같은 함수(`leaderPlayerHref`)로 바꾼 뒤 같은 테스트를 다시 돌리자 K리그1
포함 5건이 신규 알림으로 발화했다. 감시를 만들면 **일부러 깨서 우는지 확인**해야 한다.
한 번도 안 우는 감시는 없는 감시보다 나쁘다 — 있다고 믿게 만드니까.

## 백로그 18개 리그를 어떻게 지웠나 (2026-08-01 후속)

감시가 찾아준 18개 리그를 전부 처리했다. 처음 생각한 "af→ts 매핑 스크립트 재실행
(api-football ~1,100콜)" 은 **안 했다** — 진단해 보니 원인이 달랐다.

### 원인 1. 리더보드 링크 화이트리스트만 좁았다

`/players` 축구 뷰는 **36개 리그**를 지원하는데, 리더보드 링크 판정의 화이트리스트는
축구 10개뿐이었다. 나머지 26개 리그는 갈 데가 멀쩡히 있는데도 링크가 안 걸렸다.
목록이 세 군데(페이지 metadata·페이지 본문·링크 판정)에 복붙돼 있어서 벌어진 일이다.
→ `lib/players/soccer-player-page.ts` 로 단일화.

### 원인 2. 축구 선수 페이지에 시즌 폴백이 없었다

af 프로필을 단일 시즌으로만 조회했다(`m >= 7 ? y : y-1`). 8월이라 유럽 리그는
2026-27 을 묻는데 아직 데이터가 없어 통째로 404 였다.

api-football 직접 확인 (2026-08-01).

```

player 36886 · season 2025 → response 1
```

캘린더제 리그(J리그·중국·남미)는 첫 후보에서 맞아 멀쩡했고, 유럽만 죽었다.
실패 패턴이 리그 성격과 정확히 갈리는 게 단서였다. → 직전 시즌 폴백 추가.

### 이 감시의 사각지대 (알고 두는 것)

`player_link_dead`(확정 404 판정)는 `/transfers` 대상만 본다. `/players` af 뷰는
api-football 응답에 달려 있어 DB 만으로 알 수 없다. 그쪽 404 는 `route-guardian` 이
링크를 따라가며 잡는다 — 링크가 걸려 있기만 하면 그 봇의 사정권이다.
역할 분담은 **link-health = 링크가 없다 · route-guardian = 링크가 깨졌다**.

## 함정

- **비시즌 0행을 "누락" 으로 세지 말 것.** 위 4번.
- **`J2_LEAGUE` 8행처럼 표본이 얕은 리그.** 비율 임계만 쓰면 상시 알림이 된다.
- **`BOT_REGISTRY` 등록 누락.** 등록 안 하면 fallback 임계가 걸려 매일 false "다운" 이 뜬다
  (그 파일 상단 주석의 route-guardian 사례).
- **af 숫자 id 와 ts 문자열 id.** `/^\d+$/` 로 가른다. 이 규칙이 링크 판정의 핵심이고
  `LeagueLeaderBoard.playerHref` 와 `league-leaderboard.ts` 양쪽에 있다. 한쪽만 고치면 어긋난다.
