# 고확신 픽 — 컨텍스트 노트

작업 시작 2026-08-03. 사용자 요청 = "고확신 픽만 보기" 페이지 + 회원 전용.

## 왜 이걸 만드는가 — 백테스트 근거

채점된 11,611경기(2025-07-08 ~ 2026-08-02) 전수 실측. 확신도를 올리면 적중률이 오른다.

| 마켓 | 전부 픽 | 65%+ | 75%+ | 80%+ | 85%+ |
|---|---|---|---|---|---|
| 더블찬스 | 72.3% | 72.3% | 78.7% | 85.6% | 89.4%(66건) |
| 핸디캡 | 63.8% | 70.5% | 74.0% | 75.0% | 78.1%(64건) |
| 오버언더 | 56.9% | 62.6% | 67.0% | 70.2% | 70.1% |
| 1X2 | 53.6% | 61.4% | 66.9% | 71.3% | 78.9%(331건) |
| 양팀득점 | 54.8% | 55.2% | 54.5% | **42.9%** | 38.5% |

**양팀득점은 확신도가 역행한다** — 임계를 올릴수록 떨어진다. 이 마켓의 확률값은 신뢰 신호로 못 쓴다. 고확신 대상에서 제외.

종목별로도 갈린다. 농구가 압도적이고 축구 1X2 는 전체 49.0% 로 최하위.

| 마켓 | 농구 | 야구 | 하키 | 축구 |
|---|---|---|---|---|
| 1X2 85%+ | 84.6%(228) | 65.2%(92) | — | — |
| 핸디 70%+ | 85.0%(173) | 68.2%(1015) | 73.9%(786) | 73.7%(335) |

가장 강한 조합 = NBA 핸디 70%+ 85.0% · NBA 1X2 85%+ 85.3% · NBA OU 85%+ 78.8%.

## 결정 사항 (사용자 확인 완료)

- **위치** = 새 페이지 `/picks/strong` (독립 URL, 회원 게이트를 깔끔히 걸 수 있음)
- **선정 기준** = 마켓별 차등 임계 (단일 임계는 양팀득점 같은 역행 마켓을 못 거른다)
- **회원 게이트** = `/lab` 패턴 참고 — 비회원은 소개 + 미리보기 + 가입 CTA

## 막힌 것 — 먼저 풀어야 할 선결 과제

기능을 만들기 전에 확인했더니 **지금 고확신 픽이 0건**이다.

```
24시간 창: 예정 74건 · 예측보유 3 · 고확신 0건
7일   창: 예정 1110건 · 예측보유 4 · 고확신 0건
```

원인 두 가지.

**① 1X2 예측이 PREVIEW 글 생성에 묶여 있다.** `pred*` 는 [generate-previews.ts:900](../../src/jobs/generate-previews.ts) 에서 부수적으로 저장된다. PREVIEW 가 나가는 경기에만 예측이 붙어, 최근 3일 종료 경기 787건 중 1X2 보유율이 21% 다.

**② 핸디·OU·DC 는 아예 사후 계산이다.** [evaluate-predictions.ts:364](../../src/jobs/evaluate-predictions.ts) 가 **경기 종료 후 채점하면서** predOverProb·predHcProb·predDcProb 를 계산한다. 즉 예정 경기에는 구조적으로 존재할 수 없다. 최근 3일 보유율 핸디 8% · OU 8% · DC 1% 는 전부 종료된 경기다.

→ 그래서 **예정 경기 예측 생성 잡을 먼저 만든다**(사용자 결정).

부수적으로, 지금이 비시즌인 것도 겹친다. 고확신 픽이 쏟아지는 농구·하키가 8월엔 오프시즌이고 야구 1X2 는 85%+ 가 4,583건 중 92건(2%)으로 원래 희소하다. **10월 NBA·NHL 개막 전까지는 잡을 고쳐도 픽이 적을 것**이다 — 이건 버그가 아니라 계절성이다.

## 설계 메모

- 예측 계산 로직은 이미 있다. 새로 짜지 말고 재사용할 것.
  - 1X2 = `predictMatchById` (풀엔진, 선발 보정 포함) — generate-previews 가 쓰는 것과 같은 것
  - OU/핸디 = `predictTotalMarket` / `predictHandicapMarket` (SPORT_PROFILE 있는 리그만)
  - DC/BTTS = `bestDoubleChance` / `predictBttsMarket` (축구만)
- evaluate-predictions 는 같은 함수에 `m.startTime` 을 넘겨 그 시점 이전 데이터만 쓰게 한다(look-ahead 방지). 새 잡도 같은 방식이어야 백테스트 수치와 일관된다.
- **correct 필드는 건드리지 않는다** — 채점은 evaluate 잡의 몫. 새 잡은 prob/pick 만 채운다.
- 이미 예측이 있는 경기는 덮어쓸지 결정 필요. 킥오프 직전 갱신이 더 정확하지만, 사용자가 본 픽이 바뀌면 신뢰를 잃는다 → **처음 저장 후 고정**을 기본으로 본다(미확정).
