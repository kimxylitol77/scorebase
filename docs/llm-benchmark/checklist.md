## 3단계에서 배운 것 — 재현해보니 결함이 나왔다

원본을 내는 진짜 값어치는 "공개했다" 가 아니라 **내가 직접 재현해보다가 결함을 찾는 것**이었다.

- 🔴 **`width_bucket` 상한이 0.90 이라 확신도 90%+ 예측이 오버플로 버킷으로 빠졌다.**
  그게 표시 하한(n<40)에 걸려 조용히 사라졌는데, 하필 가장 과신한 구간이라
  **결과가 실제보다 순해 보였다.** 5%p 폭으로 30~100% 전체를 덮게 고쳤다.
  경계는 상수 3개(`BIN_LO`·`BIN_HI`·`BIN_COUNT`)로 뽑아 쿼리 4곳이 어긋나지 않게 했다.
- **숨긴 표본은 반드시 밝힌다.** n<40 버킷 6개(115건)가 곡선에서 빠지는데,
  그중 82.2%→82.6%(n=23) 처럼 잘 맞은 버킷도 있다. 안 밝히면 "유리한 것만 골랐다" 가 된다.
- **Prisma 함정.** 태그드 템플릿의 `${}` 는 바인드 파라미터로 나간다.
  `width_bucket` 은 `(float8, float8, float8, int)` 이라 `::float8`·`::int` 캐스트가 필요하다.
- 검증 절차는 **production CSV 를 받아 남처럼 재계산**하는 것으로 고정한다. 로컬 DB 조회로는
  "공개된 파일이 페이지와 같은가" 를 못 본다.

## 2단계에서 배운 것

- **헤드라인에 인용할 구간은 표본으로 걸러야 한다.** 격차만 보고 고르면 n=42 짜리
  가장 약한 칸(85%→64%)이 뽑힌다. `WELL_POWERED = 300` 으로 거른다.
- **McNemar 가 결정적이었다.** 독립 신뢰구간은 전부 겹쳐서 "시장이 더 낫다" 를 못 했는데,
  같은 경기로 짝지으니 8개 중 5개가 p<0.05 로 갈렸다. 같은 대상을 예측하는 비교엔 짝지은 검정이 맞다.
- **ECE 가 적중률보다 훨씬 잘 갈린다.** 적중률은 50.4~55.7%(전부 겹침)인데
  ECE 는 5.8~17.1% 로 3배 차이가 난다. 그래서 ECE 를 앞세운다.
- **meta description 에 특정 수치를 박지 말 것.** 데이터가 늘면 본문과 어긋난다.
- JSX 가 `{숫자}` 뒤 공백을 삼킨다("5 of 8forecasters") — `{" "}` 필요.
- `uppercase` 가 χ² 를 Χ² 로 바꾼다 — 통계 표기엔 `normal-case`.
- 브라우저 스크린샷이 검은 프레임을 뱉어도 페이지 문제가 아닐 수 있다.
  DOM(`getBoundingClientRect`·`getComputedStyle`)으로 교차 확인할 것.
