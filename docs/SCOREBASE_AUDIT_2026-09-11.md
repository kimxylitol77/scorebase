> 외부 감사 3차(2026-09-11) 결과를 개발 작업으로 옮긴 문서.
> 대상: scorebase.kr / 작성 근거: 홈 정밀검사 + 국내 5곳·글로벌 4곳 경쟁 분석.

## 0. 작업 원칙

1. **새 기능을 만들지 말 것.** 상위 3개 과제는 전부 "이미 있는 것을 보이게 만드는" 작업이다.
2. **신규 종목·게임성 기능은 2개월 동결.** (테니스/골프/F1/드림팀/전술판/커리어 모드 계열 추가 금지)
3. **정직한 서술을 약화시키지 말 것.** 마이너스 수익률, 표본 편중 고지, "데이터 준비 중" 표기는 이 사이트의 핵심 자산이다. 마케팅 문구로 부드럽게 바꾸지 않는다.
4. 각 과제는 **독립 PR**로. 수용 기준을 전부 만족해야 완료.

## 1. [P0] 홈 H1을 수익률 주장으로 교체

### 문제
현재 H1: `감이 아니라, 숫자로 보는 경기.`
→ 정배당·벳인포·스포키 전부 쓸 수 있는 문장. 차별성 0.
유일한 차별 자산(유닛 수익률)이 홈 어디에도 없다.

### 요구사항
- H1을 **검증 가능한 수치 주장**으로 교체.
- 권장안:
  - H1: `우리 픽의 수익률은 −5.2%입니다.`
  - 서브: `시장 인기픽은 −7.0%. 그 차이 +1.8%p가 우리 모델의 전부입니다.`
  - CTA: `10,200경기 실측 채점 기록 보기 →` → `/predictions/accuracy`
- **수치는 하드코딩하지 말 것.** 적중률 보드와 동일한 소스에서 읽어 렌더. 백테스트가 갱신되면 H1도 따라 변해야 한다.
- 수치 옆에 기준일 표기 (`2026-09-11 기준 · 1,266경기`).

### 수용 기준
- [x] `/` 의 `<h1>`에 수익률 수치가 포함되고, 값이 `/predictions/accuracy`의 「플랫 유닛 수익률」과 항상 일치한다.
- [x] 백테스트 데이터를 갱신하면 재배포 없이 H1 수치가 바뀐다.
- [x] meta description / og:description 도 같은 주장으로 교체.
- [x] 수치 소스가 없거나 로딩 실패 시 fallback 문구가 뜨고, 잘못된 숫자가 노출되지 않는다.

## 2. [P0] 상단 네비에 「배당」 메뉴 신설

### 문제
- `/value-bets` 와 `/predictions/accuracy` 가 **푸터에서만** 접근 가능. 3회 연속 지적에도 미착수.
- 「베트맨 배당」은 `/odds` 의 4번째 탭에 숨어 있음.
- 현재 상단 네비 목적지 41개, 분류 기준이 **종목**이라 행동 기준으로 찾는 사용자가 도달하지 못함.

### 요구사항
상단 네비에 `배당` 항목 추가. 하위 구성:

| 라벨 | 경로 | 설명문 |
|---|---|---|
| 배당 흐름 | `/odds?sport=soccer` | 오픈 대비 변동 · 돈이 몰리는 방향 |
| 밸류 베트 | `/value-bets` | 모델이 시장보다 자신 있는 경기 |
| 베트맨 승부식 | `/odds?sport=betman` | 국내 합법 · 프로토 배당·투표 분포 |
| **수익률 보드** | `/predictions/accuracy` | **실배당 채점 — 적중률·유닛 수익률** |

- 각 종목 드롭다운(축구/야구/농구)에 중복으로 들어가 있는 「배당 흐름」은 그대로 두되, 「배당」 메뉴가 정본이 되게 한다.
- 모바일 네비에도 동일하게 반영.

### 수용 기준
- [ ] 데스크톱·모바일 모두 상단 1클릭으로 `/value-bets`, `/predictions/accuracy`, `/odds?sport=betman` 도달 가능.
- [ ] 키보드 탐색(Tab/Enter)과 스크린리더로 열리고 닫힌다.
- [ ] 현재 페이지가 하위 항목일 때 「배당」이 활성 상태로 표시된다.

## 3. [P0] 홈 첫 화면에 오늘 주요 경기

### 문제
라이브스코어 사이트인데 스크롤 없이 보이는 영역에 경기가 0건.
Flashscore·Sofascore·FotMob·네이버스포츠 전부 첫 화면이 경기 목록.
또한 현재 「오늘의 AI 매치 인사이트」가 3경기 전부 야구로 나오는 사례 확인(EPL 경기일 기준).

### 요구사항
- 히어로 세로 높이를 현재의 **절반 이하**로 축소.
- 히어로 바로 아래 `오늘 주요 경기 6` 블록 배치.
- 경기 선정 우선순위: **① 로그인 사용자의 관심팀 → ② 현재 시각 ±3시간 내 킥오프 → ③ 리그 티어(빅5·K리그·UCL 우선)**.
- 종목 쿼터 적용: 축구 최소 3경기 보장 (해당일 축구 경기가 3개 미만이면 예외).
- 각 카드에 **배당(1X2) 또는 모델 확률 중 하나 이상**을 노출. 라벨(`승/무/패`) 필수.

### 수용 기준
- [ ] 1280×800 및 390×844 뷰포트에서 **스크롤 없이** 경기 카드가 최소 1개 보인다.
- [ ] 축구 경기가 있는 날 첫 화면 6경기 중 최소 3경기가 축구다.
- [ ] 비로그인 사용자도 동일 블록을 본다(관심팀 조건만 스킵).
- [ ] 홈 DOM 요소 수가 현재(1,672) 대비 +30% 이내를 유지한다.

## 4. [P1] `/picks` 를 「내 베팅 기록장」으로 재정의

### 문제
- 현재 `/picks` 는 적중률만 기록(`적중 1/2 (50%)`). **배당을 저장하지 않음.**
- 모델 픽은 유닛 수익률을 공개하는데 **사용자 본인 픽은 같은 기준으로 볼 수 없다** — 기준을 만들어놓고 유저에게 안 준 상태.
- 경쟁사 스포라이브가 "국내 유일 합법 승부예측 + 리워드"로 같은 영역을 선점. 리워드 게임으로는 조건이 불리하므로 **성격을 바꿔야 한다.**

### 요구사항
1. 픽 저장 시 **그 시점의 배당(해외 25곳 평균)과 저장 시각을 함께 기록**한다. (최우선 — 이것만 해도 나머지는 나중에 계산 가능)
2. `/picks` 상단 지표를 교체:
   - 기존: `내 투표 3 / 적중 1/2 (50%)`
   - 변경: `내 픽 N · 적중률 X% · 평균 배당 Y · 누적 Zu · 수익률 W%`
   - 계산 로직은 `/predictions/accuracy` 의 「플랫 유닛 수익률」 컴포넌트를 **재사용**한다(중복 구현 금지).
3. 문구에서 "AI를 이기는 중" 류의 적중률 기반 비교를 제거하거나, 수익률 기반으로 교체.
4. `/lab` 백테스트 결과에도 동일 유닛 수익률 카드를 추가한다(현재 적중률 54.4%만 노출).

### 수용 기준
- [ ] 신규 픽 1건 저장 후 DB에 `odds_at_pick`, `picked_at` 이 기록된다.
- [ ] 종료 경기 채점 시 유닛 손익이 계산되어 `/picks` 상단에 반영된다.
- [ ] 배당 정보가 없는 경기의 픽은 **수익률 계산에서 제외**되고, 화면에 제외 건수가 표기된다(`배당 없음 N건 제외`).
- [ ] `/lab` 백테스트에 적중률과 유닛 수익률이 함께 표시된다.

## 5. [P1] CLV(종가 대비 가치) 도입

### 문제
경기당 배당 스냅샷을 41~131회 수집 중이면서 **종가를 판정에 쓰지 않는다.**
CLV는 표본 50경기로 신호가 나오지만 ROI는 1,000경기가 필요하다 — 사용자에게 훨씬 빨리 의미 있는 피드백을 줄 수 있는 지표.
OddsPortal의 해자가 정확히 이 종가 아카이브다.

### 요구사항
1. **[선행 · 즉시] 종가 스냅샷 보존 정책 확정.** 킥오프 직전 마지막 스냅샷을 경기 단위로 영구 보존. 롤링 삭제·TTL이 걸려 있다면 지금 해제한다. — *데이터를 버리면 되돌릴 수 없다. 나머지 구현이 늦어져도 이것만은 먼저.*
2. 픽 단위 CLV 계산: `CLV% = (내 픽 시점 배당 / 종가 배당 − 1) × 100`
3. `/picks` 에 `평균 CLV +X.X%` 표기. 개별 픽 행에도 개별 CLV.
4. 모델 픽에도 동일 적용 → `/predictions/accuracy` 에 「모델 평균 CLV」 추가.

### 수용 기준
- [ ] 종가 스냅샷에 삭제 정책이 걸려 있지 않음을 확인하는 테스트/문서가 있다.
- [ ] 종료 경기에 대해 CLV가 계산되어 저장된다.
- [ ] 종가를 확보하지 못한 경기는 CLV 집계에서 제외되고 제외율이 노출된다.
- [ ] CLV 정의와 해석(양수 = 시장보다 좋은 값에 잡았다)이 화면 내 설명으로 제공된다.

## 6. [P1] 밸류 베트 사후 수익률 백테스트

### 문제
`/value-bets` 는 노비그 확률과 켈리 비중까지 갖췄으나(양호), **이 픽들이 실제로 수익이 났는지를 보여주지 않는다.**
현재 페이지 문구도 "종료된 매치는 적중률 보드 별도 페이지에서"로 미루고 있는데, 적중률 보드는 *모델 픽 전체* 수익률이지 *밸류 베트만의* 수익률이 아니다.
경쟁사(정배당)가 못 하는 지점이므로 완성하면 명확한 차별점이 된다.

### 요구사항
- 종료된 밸류 베트(edge ≥ +5%p)만 따로 집계해 다음을 공개:
  - 표본 수 / 적중률 / **평균 배당** / **누적 유닛** / **ROI%**
  - 배당 구간별(≤2.0 / 2.0~3.0 / >3.0) 분해 — 롱샷 구간에서만 손실이 나는지 확인 가능해야 함
  - edge 크기별(5~10%p / 10%p+) 분해
- `/value-bets` 상단에 요약 1줄 + 상세 페이지 링크.

### 수용 기준
- [ ] 배당 구간별·edge별 분해가 모두 표시된다.
- [ ] 표본 100건 미만 구간은 수치와 함께 **표본 부족 경고**를 띄운다.
- [ ] 결과가 마이너스여도 그대로 노출한다(숨기거나 필터링 금지).

## 7. [P2] 배당 소스 단일화 (잔여 이슈)

### 문제
한 경기 상세 페이지 안에서 같은 홈 배당이 서로 다른 값으로 노출된 사례:

| 위치 | 값 | 표본 |
|---|---|---|
| 라이브 배당 | 2.20 | 11곳 |
| 북메이커 비교 | 2.22 | 13곳 |
| 시장별 배당 | 2.23 | 25곳 |
| 매치 인사이트 탭 | 2.23 | 25곳 |

표본 곳수가 달라 값이 다른 건 정상이지만, **사용자는 어느 값이 기준인지 알 수 없다.**

### 요구사항
- 페이지 내 **기준 소스를 「해외 25곳 평균」 하나로 통일.**
- 11곳/13곳 집계는 해당 마켓만 지원하는 북이 있을 때만 사용하고, 그 경우 값 옆에 `(11곳)` 을 반드시 병기.
- 배당 블록이 페이지 내에서 3회 이상 반복되고 있으므로 중복 섹션을 통합한다.
- 마진(vig) 표기도 한 곳에서만, 같은 정의로.

### 수용 기준
- [ ] 임의의 경기 상세 페이지에서 같은 마켓·같은 선택지의 배당이 서로 다른 값으로 2회 이상 노출되지 않는다. (다른 표본을 의도적으로 병기하는 경우는 곳수 라벨 필수)
- [ ] 배당 섹션 중복이 제거되어 페이지 길이가 줄어든다.

## 10. [P2] 채점 방법론 페이지 전면 배치

### 배경
국내 최대 경쟁자 정배당의 데이터 규모는 **31만 경기 / 173리그**. 스코어베이스의 채점 표본은 **10,200경기**. 규모로는 못 이긴다.
유일한 대응은 **"세는 것"과 "채점하는 것"의 차이**를 명확히 하는 것.

### 요구사항
- `/방법론`(methodology) 페이지를 홈·적중률 보드·밸류베트에서 모두 링크.
- 페이지에 반드시 포함:
  - 채점 시점 정의(경기 전 확정, 사후 수정 없음)
  - 사용 배당의 출처와 시점(킥오프 전 마지막 북메이커 평균)
