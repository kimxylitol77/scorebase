# 부상자 영향 모델 — 컨텍스트 노트

시작 2026-08-03. 사용자 지시 두 가지.

1. **부상자 스냅샷을 저장하라** (승률 반영은 나중 — 백테스트가 먼저)
2. **부상자 수를 세면 안 된다.** "부상자가 없다고 그 팀에 점수를 주는 게 아니다.
   실질적으로 선발인지 계산해야 한다. 후보 부상했다고 질 것 같이 계산하면 안 된다."
3. 다른 곳은 어떻게 하는지 조사하고 신중하게 적용하라

## 조사 — 업계는 어떻게 하나

**결론부터. 최상급 모델도 부상 조정을 조심스럽게 한다.**

- **Nate Silver PELE** — 정규 레이팅은 **부상을 아예 반영하지 않는다.** 월드컵 때만 26인 로스터
  중 최적 23인을 뽑아 알고리즘 로스터와 비교해 조정한다. 본인도 "언론 보도를 가용성 예측으로
  옮기는 데 추측이 들어간다"고 인정하고, "로스터가 깊어 부상 영향은 대체로 작다"고 적는다.
- **Transfermarkt 가치 기반 논문** — 팀 전체 가치가 아니라 **그 경기 라인업의 가치**를 쓴다.
  결장자가 자연히 빠지므로 부상 보정이 내장된다. 이 방식이 FIFA 랭킹보다 예측력이 좋았고
  북메이커 대비 켈리 베팅에서 양의 수익을 냈다.
- **부상 영향 가중** — 결장 여부가 아니라 **평소 출전 시간·포지션**으로 가중한다. 센터백·GK 는
  실점 기대(xGA)에 영향이 커 따로 본다.

→ 우리도 **"몇 명 빠졌나"가 아니라 "빠진 선수들이 평소 팀 출전 시간의 몇 %를 먹던 선수인가"**
로 가야 한다. 사용자 지시와 업계 방법론이 같은 곳을 가리킨다.

## 우리 데이터 실측 (2026-08-03)

| 재료 | 상태 | 판정 |
|---|---|---|
| `player-season-stats.json` | 4,612명 중 **starts·minutes 보유 4,367(95%)** · 빅5 충실(LALIGA 732·EPL 667·LIGUE_1 652·BUNDESLIGA 592·SERIE_A 583) | **주전 판별의 핵심 재료** |
| `ts-af-player-map.json` | ts→af 3,553명. 시즌스탯 선수의 77%, **빅5 는 88%** | 부상자(af id) ↔ 스탯(ts id) 연결 가능 |
| `PlayerMarketValue` | 13,849명 전원 currentValue 보유 | 보조 가중치로 쓸 수 있음 |
| `Match.lineupHome/Away` | 최근 180일 3,789건(18%)뿐이고 **선수 id 없이 이름 문자열만**("Robin Roefs"). 상위 리그가 클럽친선·아르헨2부라 빅5 빈약 | **주전 판별에 못 씀** |
| 부상자 | api-football `/injuries` → **in-memory 캐시만. DB 없음** | 그래서 스냅샷이 필요 |

라인업이 쓸 수 없다는 게 중요하다. 그래서 "실질 선발" 판별은 **시즌 누적 `starts`·`minutes`**
로 간다 — 실제 기용을 반영하므로 시장가치(잠재력·명성이 섞임)보다 낫다.

## 설계 결정

**저장할 것 = 부상자 명단 + 그 시점의 주전 지표**

시즌스탯은 계속 갱신된다. 나중에 조회하면 "지금" 값이지 "그때" 값이 아니다. 백테스트하려면
**스냅샷 시점의 주전 지표를 함께 박아둬야** 한다. 이게 이 테이블의 존재 이유다.

핵심 파생값 = **`teamMinutesShare`** — 그 선수의 시즌 출전 시간 ÷ 같은 팀 선수들 출전 시간 합.
후보(share 1~2%)와 주전(share 8~10%)이 자연히 갈린다. 사용자가 말한 "후보 부상했다고
질 것처럼 계산하면 안 된다"가 이 한 컬럼으로 해결된다.

**지금 하지 않는 것**
- 승률 계산에 반영 — 데이터가 몇 달 쌓이고 백테스트를 통과해야 한다.
  기존 원칙 "새 시그널은 백테스트 통과만"([[baseball-accuracy-findings]]).
- 부상자 수 기반 가중 — 사용자가 명시적으로 금지.

## 주의

- 스키마 추가는 프로덕션 DDL 이다. 메모리 `prod-ddl-lock-incident` — ALTER 전 장기 트랜잭션
  확인 + `lock_timeout` 짧게. 신규 테이블 CREATE 는 기존 테이블 락을 잡지 않아 상대적으로 안전.
- api-football `/injuries` 는 리그·시즌 단위 호출이다. 일일 쿼터를 고려해 리그 수를 제한한다.
- 부상자 명단은 **"오늘 못 뛴다"가 아니라 "부상 보고가 있다"** 이다. PELE 가 지적한 모호함이
  우리에게도 그대로 있다 — 백테스트 때 이 잡음을 감안할 것.
