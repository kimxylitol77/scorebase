# 헤르메스 뉴스데스크 — 글감 편집장 봇 계획

> 2026-09-13. 헤르메스 에이전트(`~/.hermes`, Nous Research)에 스코어베이스 전용 서브 에이전트를 붙이는 첫 단추.
> 참고 영상: 티타임즈 "자율형 AI에이전트 너무 쉬워졌다" (김민정 HRX랩, 2026-09-12).

## 무엇을

헤르메스 프로필 `newsdesk`(글감 편집장)가 매일 한 번,
**수집만 되고 발행되지 못한 해외 기사 중 큰 이슈**를 골라
**스코어베이스 DB 데이터를 붙인 자체 기사 글감**을 1~3개 제안한다.

사용자가 승인한 글감만 다음 단계(초안 → 발행)로 간다. 헤르메스는 **찾고·제안하고·초안까지만** 한다.
발행·코드 반영은 사용자 승인 후 Claude Code 세션이 기존 `/blog` 발행 절차로 한다.

## 왜 (2026-09-13 실측, 최근 14일)

| 종목 | 수집 | 발행 |
|---|---|---|
| 축구 | 2,953 | 61 (하루 약 4건, 캡 16) |
| 야구 | 629 | 0 |
| 농구 | 555 | 0 |
| 하키 | 551 | 0 |

- 병목은 수집이 아니라 **재료**. 소스 대부분이 제목만 줘서 `MIN_MATERIAL_CHARS=500` 게이트에서 탈락.
  야구·농구·하키는 본문을 주는 소스가 없어 0건.
- 발행분 61건 중 27건이 TRANSFER — 이적 편중 여전.
- 그런데 36시간 storyKey 클러스터를 보면 **여러 매체가 동시에 다룬 큰 이슈**가 매일 있다
  (예. arsenal-sunderland 6건/3매체, 마크 스톤 골든나이츠 재계약 3건/2매체). 이것들이 글감 원석.
- 남의 기사를 옮기지 않고 **우리 데이터(순위·Elo·기록·예측)로 쓰는 글**은 저작권 걱정이 없고,
  검색 회복 레버("양질 ANALYSIS 직접 작성", `feedback_ai_visibility_seo`)와 방향이 같다.

## 하지 않는 것 (범위 밖)

- 뉴스를 새로 긁어 오거나 사이트에 직접 발행하지 않는다 — 기존 `fetch-news-briefing.ts`(2h)와
  맥미니 `sports-news-brief.js`(07시)와 중복이고, 번역 금지·원문 대조 검증 게이트를 우회하게 된다.
- 운영 DB 쓰기, git commit/push, `.env*` 읽기 권한을 주지 않는다.
- 원문 번역·요약 금지 (브리핑 파이프라인과 같은 저작권 원칙).

## 구조

```
[헤르메스 cron, 매일 1회, 프로필 newsdesk]
  └─ --script: ~/.hermes/profiles/newsdesk/scripts/material.sh
        └─ node --env-file=.env.local scripts/newsdesk-material.mjs   (scorebase, 읽기 전용 쿼리)
             · 36h NewsBriefing storyKey 클러스터 (기사 수·매체 수·최고 score·제목·원문 URL)
             · 클러스터에 등장한 팀 → Team(name/league) 매칭 → 순위·Elo·최근 경기 등 우리 데이터
             · stdout JSON → 에이전트 프롬프트에 주입
  └─ 에이전트(SOUL.md = 글감 편집장 규칙)
        · 글감 1~3개 선정, 각 글감마다 — 제목안, 헤드 검색어 1개, 붙일 우리 데이터, 원문 출처, 왜 지금
        · 재료에 없는 사실·수치는 쓰지 않는다
  └─ --deliver: 텔레그램(연동 후) / 그 전엔 local
[사용자] 채택할 글감 회신
[Claude Code 세션] 채택 글감 → 데이터 조회 → /blog 발행 (기존 _create-blog-*.ts 패턴)
```

## 단계

- **v1 — 제안서만** (이번 작업). 2주 운영하며 품질 확인.
- **v2 — 초안까지.** 채택된 글감을 헤르메스가 본문 초안(md)으로 작성. v1 품질이 기준을 넘을 때만.
- **v3 — 이관·확장.** 노트북은 꺼지면 cron 이 안 돈다 → 24시간 맥미니로 헤르메스 이관.
  이후 소스 스카우트·품질 검수 봇 추가 검토 (영상 조언대로 봇은 하나씩).

## 성공 기준 (v1, 2주)

1. 제안서의 사실·수치가 주입된 재료와 어긋나는 사례 0건 (매 제안서 대조).
2. 채택 가능한 글감이 주 2건 이상.
3. 노트북이 켜져 있던 날 cron 실행 누락 0건 (`hermes -p newsdesk cron runs`).

## 열린 결정

- 모델 — 기본은 무료 `muse-spark-1.3-contributor-free`. 첫 3회 제안서 품질을 보고 Kimi 유지 여부 결정.
- 실행 시각 — 브리핑 파이프라인이 밤사이 쌓인 뒤인 KST 09:00 가안.
- 텔레그램 연동은 사용자가 `hermes gateway setup` 을 마친 뒤 deliver 를 바꾼다.
