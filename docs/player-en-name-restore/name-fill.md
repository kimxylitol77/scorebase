# 선수 한글명 빈칸 채우기 (2026-08-07)

`scripts/build-football-player-names-haiku.ts --from-db --wiki`.

## 원인 — 파이프라인 사이의 구멍

기존 음역 빌더는 `TheSportsMatchCache.lineup` 만 훑는다. 그래서 **출전 기록이 없는 선수는
구조적으로 대상 밖**이었다. 그런데 빈칸 3,885명 중 **3,861명이 몸값 데이터를 가진** 선수라,
`/transfers` 에 영문 이름 그대로 노출되고 있었다. 크바라츠헬리아(€85M)·살리바(€50M) 도 그중이었다.

`--from-db` 는 라인업 대신 **DB 의 `nameKo IS NULL`** 을 대상으로 삼아 이 구멍을 메운다.
이 모드는 `name`(영문)을 건드리지 않는다 — 앞선 복구 결과를 다시 흔들면 안 된다.

## 소스 우선순위와 실측

| 소스 | 결과 |
|---|---|
| en위키 ko langlink 정본 | **909건** (조회 대비 약 24%) |
| Haiku 음역 | **2,892건** |
| 채우지 못함 | 90건 — 영문으로 표시된다 |

위키 정본률이 예상보다 훨씬 높았고 품질도 확실하다 — 베르바토프·애슐리 콜·로시츠키·캄비아소가
전부 국내 통용 표기로 들어왔다. **haiku 보다 먼저 위키를 조회하는 게 값을 한다.**

## ts 가 이름에 중국식 가운뎃점을 준다

`Khvicha·Kvaratskhelia` 처럼 `·` 로 이름을 구분한 행이 687건 있다. 이대로는 위키 조회도 음역도
빗나가므로 **입력 단계에서 공백으로 편다**(`normalizeEn`). `name` 컬럼 자체는 원본을 보존한다.

## ⚠️ 정제 로직이 헐거웠다 — 96건이 새어 있었다

기존 검사는 "한글이 한 글자라도 있으면 통과 + 한자 2자 이상이면 버림" 뿐이었다. 아래가 전부 통과했다.

| 유형 | 실제 사례 |
|---|---|
| 탭 혼입 | `후르칸\t조르바` · `오가와\t코키` |
| 가나 잔여 | `기아코모 벤ヴェ누티` |
| 원문 잔여 | `니콜라 부야디노비치ć` · `레오 Ø스티가르드` · `조ン 할리` |
| 끝 쉼표 | `셰일론,` · `탈레스 마그노,` |
| 영문 미변환 | `raffaele 루비노` · `에밀리아노 알onso` |
| 1글자 | `홀`(J. Hall) · `바`(sallieu bah) |

`sanitizeKo()` 로 교체했다. 탭·개행을 공백으로 펴고 끝 문장부호를 떼되, **라틴·가나·한자가 남으면
버린다**(= 그 선수는 영문으로 표시된다). 한글 2글자 미만도 버린다.

기존 96건은 39건 교정(탭·쉼표 제거) + 57건 `null` 되돌림으로 정리했다. **`null` 로 되돌리면
다음 `--from-db` 실행의 재시도 대상이 된다** — 실제로 그중 124건이 다시 채워졌다.
locks 등재분은 정리 대상에서 제외했다.

## 남은 90건

대부분 원본이 이니셜뿐이거나(`A. Córdoba`·`D. Sing`·`I. Johnston`) haiku 가 스스로 건너뛴 것들이다.
기존 프롬프트의 **"자신없으면 그 entry 제외(틀린 음역보다 누락이 나음)"** 원칙이 그대로 살아 있고,
이 경우 영문 표시가 정답이다. `Emiliano Alonso` 처럼 아쉬운 것도 섞여 있으나 개별 처리는 하지 않았다.

## 판단 보류

`William Saliba` 의 ko위키 표제어는 **"윌리암 살리바"** 이고 그대로 넣었다. 국내 축구 미디어는
"윌리앙" 도 쓰지만 어느 쪽이 통용인지 단정할 근거가 없어 위키를 따랐다. 바꾸려면 locks 에 등재하면 된다.
(위키 표제어 ≠ 국내 통용 문제는 메모리 `player-name-manual-fix` 참조.)
