# 컨텍스트 노트 — 과제 3 홈 오늘 주요 경기

## 계획 시점 결정 (2026-09-11)
- **관심팀은 localStorage**(`useFavoriteTeams`, 회원은 fav-server-sync 로 서버 동기) — 서버 렌더가 모른다. 순위 ①은 클라이언트에서. 지시서의 "로그인 사용자" 조건은 우리 구조에선 "저장된 관심팀이 있는 방문자" 로 읽는다(비로그인도 별표를 저장할 수 있어 기준 3 "비로그인 동일 블록"과 자연 일치).
- **ISR 1h 와 신선도**: 홈 재생성 비용(Monte Carlo) 때문에 revalidate 는 못 낮춘다. 기존 `/api/matches/by-ids`(force-dynamic, 50개)가 상태·점수를 주므로 새 라우트 없이 클라이언트가 마운트 시 1회 + LIVE 있으면 60s 갱신. 배당·확률은 갱신 안 함(1h 낡아도 표시용으로 허용, 카드에 "경기 전 기준" 명시 안 함 — 배당 자체가 시점값이라 라벨은 시각으로 충분).
- **hydration**: 첫 렌더는 서버 `now`·관심팀 없음으로 계산 → 서버 HTML 과 동일. 마운트 후(`mounted` from useSyncExternalStore) 재계산. `Date.now()` 를 렌더 중 직접 쓰지 않는다.
- **후보 범위**: ARTICLE_LEAGUES(기존 쇼케이스와 같은 화이트리스트 — 마이너 리그 배제). KST 오늘(LIVE·SCHEDULED·FINISHED). 6개 미만이면 +24h 확장(새벽·비시즌 공백).
- **티어**: 0 = UCL·EPL·LALIGA·BUNDESLIGA·SERIE_A·LIGUE_1·K_LEAGUE_1 (지시서 "빅5·K리그·UCL 우선"), 1 = KBO·MLB·NPB·NBA·NHL·UEL·UECL·WORLD_CUP·MLS·J1, 2 = 나머지.
- **±3h 판정은 이진 버킷**, 그 안에서는 |Δ| 근접 순. 종료 경기는 Δ = now − kickoff 라 3h 지나면 자연히 뒤로 간다(종료 경기를 아예 빼지 않는 이유: 저녁 시간대 방문자는 "오늘 결과"를 먼저 찾는다 — 경쟁사 첫 화면도 종료 포함).
- **축구 쿼터**: 정렬 후 축구를 먼저 3개 뽑고 나머지 3개를 순서대로 채운 뒤 전체를 순위로 재정렬. 축구 후보 <3 이면 있는 만큼(지시서 예외).
- **배당 vs 확률**: 카드 하단 한 줄. oddsHome 있으면 배당(승/무/패, 무승부 없는 종목은 승/패), 없으면 predHome 확률, 둘 다 없으면 "배당 준비 중". 배당은 vig 포함 표시용 원배당(oddsX), 확률은 모델(predX) — 라벨로 구분.
- **기존 HomeAiInsightShowcase 제거**: 새 블록이 역할(가까운 경기 + 모델 확률)을 포함하고, 리그 전체 매치 로드 3회는 홈 렌더 비용의 큰 몫이었다. EN 미러 파일·사전도 함께 제거(내 변경으로 고아가 되는 것만).
- **DOM 기준선**: 운영 홈 1,605 요소(2026-09-11 실측, 지시서 1,672 는 작성 시점). 상한 1,605 × 1.3 = 2,087.

- **prisma 가 브라우저 번들에 들어가는 함정**: 순수 순위 함수와 로더를 한 모듈에 두면 클라이언트 컴포넌트가 import 할 때 PrismaClient 가 따라와 홈이 에러 바운더리로 떨어진다("PrismaClient is unable to run in this browser environment"). `today-matches-rank.ts`(순수) / `today-matches.ts`(서버 로더) 로 분리.
