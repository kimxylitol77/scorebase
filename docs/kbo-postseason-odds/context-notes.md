# KBO 가을야구 확률 컬럼 — 컨텍스트 노트

## 왜 하는가

경쟁사 aikball.com(오야리) 정밀 분석(2026-07-29)에서 가장 먼저 흡수할 항목으로 뽑힘. 순위표 안에 포스트시즌 진출 확률이 붙어 있으면 "순위표"라는 검색 의도로 들어온 사용자가 우리 예측 자산을 바로 만난다. 우리는 몬테카를로가 이미 돌고 있어 신규 모델링이 0이다.

## 결정과 근거

**KBO 만 한다.** `runMonteCarlo` 는 리그를 단일 표로 시뮬레이션하고 `top5` 를 낸다. KBO 포스트시즌은 정규시즌 상위 5팀이므로 정확히 일치한다. MLB(지구 6 + 와일드카드 6, AL/NL 분리)·NPB(CL/PL 각 3위)는 구조가 달라 같은 `top5` 를 쓰면 틀린 숫자가 된다. `api/cron/league-sim-snapshot/route.ts:60` 주석이 이미 이 한계를 적어 놓았다. 경쟁사가 홈에서 백테스트를 "실측"이라 부른 것을 지적한 직후에 우리가 구조 무시 확률을 노출하면 같은 부류의 실수다.

**스냅샷(`LeagueSimSnapshot`)이 아니라 라이브 계산을 쓴다.** 스냅샷은 팀을 이름 문자열로 저장해 조인이 약하고 하루 1회(07:00 KST)라 당일 경기 결과가 반영되지 않는다. 순위표는 매일 갱신되는 표라 옆 칸의 승패와 확률이 어긋나 보이면 안 된다.

**두 페이지가 같은 계산을 공유한다.** 몬테카를로는 `Math.random()` 기반이라 시드가 없다(`monte-carlo.ts:31`). 같은 데이터로 5,000회를 두 번 돌리면 확률이 ±1%p 흔들린다. `/standings/KBO` 와 `/predictions/KBO` 가 각각 돌리면 같은 사이트에서 같은 지표가 다르게 보인다. 그래서 `unstable_cache` 로 감싼 `getKboSeasonSim()` 하나를 두 페이지가 호출한다. 캐시 TTL 600초는 `/predictions/[league]` 의 `revalidate` 와 맞춘 값이다.

**시즌 창 로딩 로직은 `/predictions/[league]` 의 것을 그대로 옮겼다.** `currentSeasonStart` → FINISHED<10 이면 `previousSeasonStart` 폴백. 두 페이지가 다른 매치 집합을 보면 캐시를 공유하는 의미가 없다.

## 표기 규칙

- 확률은 몬테카를로 상한 0.999 캡이 이미 걸려 있다(`monte-carlo.ts:221-227`). 수학적으로 확정이어도 `99.9%` 로 나온다. 의도된 동작이라 그대로 둔다.
- 0.1% 미만은 `<0.1%` 로 쓴다. "탈락"이라 단정하지 않는다 — 표본 기반 추정이라 매직넘버 탈락 판정과 다르다.
- 시즌 종료(잔여 경기 0) 시 컬럼을 숨긴다. 확정된 결과에 확률을 붙이면 오히려 혼란스럽다.

## 함정

- `/standings/[league]` 의 야구 분기는 `isBaseball = KBO || NPB` 다. 컬럼 노출 조건은 `showGb` 와 같은 KBO 전용 플래그(`showPostseason`)로 따로 뒀다. NPB 를 나중에 켤 때 `isBaseball` 을 건드리면 안 된다.
- 순위표 렌더 코드는 사이트에 3벌(`StandingsOnlyView`, `LeagueStandingsTable`, `standings/[league]/page.tsx` 인라인)이다. KBO 순위표는 인라인 한 곳에서만 나오므로 이번엔 한 곳만 고쳤다. 축구로 확장할 일이 생기면 3곳 동기화가 필요하다.
