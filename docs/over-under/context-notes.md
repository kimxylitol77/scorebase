# 오버/언더 통계 페이지 — 컨텍스트 노트

작성 2026-08-21. 결정과 근거를 계속 덧붙인다.

## 배경 · 목표

사용자 요청. "오버 많이 나는 리그·팀, 언더 많이 나오는 팀"을 하부리그까지 전부 보여주고,
데이터가 쌓이면 자동으로 갱신되는 구조. 핵심 키워드는 오버·언더.

## 결정 1 — 블로그 글이 아니라 전용 페이지 (2026-08-21, 사용자 선택)

리그가 99개(팀 1,500+)라 글 한 편에 담으면 표가 1,500행이 되고, 리그별 검색어가 한 주소로 몰린다.
리그마다 전용 페이지를 두면 "분데스리가 오버", "K리그2 언더" 같은 검색어를 각각 잡는다.

부수 효과가 더 크다. 페이지가 DB 를 직접 읽으므로 **주 1회 재생성 cron 자체가 필요 없다**.
경기가 끝나 Match 가 FINISHED 로 바뀌면 다음 렌더에서 곧바로 반영된다.
블로그 허브 글만 주 1회 갱신하면 된다.

## 결정 2 — 집계 기간은 롤링 윈도가 아니라 "보유 전체"

"데이터가 계속 쌓인다"는 요청이라 최근 N일로 잘라내면 의도와 어긋난다.
FINISHED + 스코어 보유 경기를 전부 집계하고, 페이지에 집계 기간과 경기 수를 명시한다.
현재 보유 데이터는 2025-08 부터라 실질적으로 1년치다.

## 결정 3 — 대상 리그 필터

- 축구만. SOCCER_LEAGUES 기준 (오버 2.5 는 축구 전용 개념 — 야구·농구는 NBA 100%, MLB 96% 로 무의미).
- 컵·친선 제외. 팀당 평균 경기 수가 적어 팀 단위 비율이 튄다
  (CLUB_FRIENDLY 는 938팀에 1,550경기, UECL 은 240팀). **팀당 평균 10경기 이상**인 대회만 넣는다.
- 리그 총 30경기 이상.

## 결정 4 — 표시 지표

오버 2.5 를 주력으로 하되 1.5·3.5 를 함께 보여준다. 여기에 경기당 평균 득점, 득점/실점 분해,
홈/원정 분리를 더한다. 언더는 오버의 여집합이라 같은 표에서 역순 정렬로 처리한다(별도 계산 없음).

## 함정 메모

- 팀명은 반드시 `toKoreanTeamName(name, league)` 로 정규화한다. 원문 그대로 쓰면 같은 팀이 갈린다
  (2026-08-13 이적료 집계에서 EPL 7팀 누락 사고).
- `unstable_cache` 는 배포 사이에도 유지된다. 집계 로직을 바꾸면 캐시 키의 버전을 올려야 한다.
- 표·콜아웃에 흰 배경을 쓸 때는 color 를 명시한다. 다크 테마에서 글자가 흐려진다(2026-08-21 블로그 사고).
