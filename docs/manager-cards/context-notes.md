# 결정 기록

- 2026-09-28 엔진은 satori 유지. 새 의존성 없이 기존 폰트·캐시 헤더·이미지 로더(`weekly-frame.tsx`)를 재사용한다.
- 프레임은 새로 만든다. 기존 `Frame` 은 흰 글씨 고정이라 라이트 테마를 못 쓴다.
- 시즌 기록·리그 순위는 글에 저장돼 있지 않아 DB 경기에서 계산한다(시즌 시작 7월 1일 ~ 해당 월 말).
- 경쟁 후보의 감독 이름은 검증된 출처가 없어 카드에는 팀 이름만 쓴다.
- 링 카드 숫자는 116px. 150px 에서는 "100%" 가 원을 넘쳤다.
- 경기 기록 카드는 경기 수(3·4·5 이상)에 따라 줄 높이를 바꾼다. A매치 기간이 낀 달은 3경기뿐이라 고정 높이면 아래 절반이 빈다.
- 로컬 렌더는 장당 30~70초 걸렸다. dev 서버가 Neon 연결 풀을 같이 써서 그렇고, 데이터 로딩이 실패하면 폴백 카드(40KB 안팎)가 나온다. 샘플 생성 스크립트는 용량 60KB 미만이면 다시 받는다.
- 샘플 12장은 `samples/` 에 보관(글 #5687 기준, 2026-09-28 생성).
- 2026-09-28 2차. 사용자가 "더 없냐, 깃허브 확인한 거냐"고 지적 — 1차는 검색 요약만 읽었다. 저장소·갤러리를 직접 열어 5종을 추가했다.
- satori 는 svg 안의 글자를 못 그린다. 차트는 도형만 svg, 글자는 절대 위치 div.
- 선수 카드형 능력치는 실측이 아니라 **이달 리그 내 백분위를 60~99 로 환산**한 값이다. 카드 부제에 명시했다. 본문에서 "능력치 96" 을 사실처럼 쓰지 말 것.
- 백분위 재료는 경기 결과와 경기 전 예측뿐이다(승점·득점·실점·득실·무실점·기대 대비). 점유율·슈팅 같은 내용 지표는 전 구단 집계가 없어 넣지 않았다.
- 순위 흐름의 라운드는 날짜가 아니라 "각 팀의 첫 k경기"다. 연기 경기가 있어도 팀마다 같은 경기 수로 비교된다.
- dev 서버 로그는 필터 없이 읽지 말 것. 홈 화면의 Neon 풀 타임아웃이 수백 줄 쏟아진다.
- 2026-09-29 사용자 선택: 2차 5종(포스터·덤벨·피자·순위 흐름·선수 카드형)을 글에 넣는다. 1차 4종(hero·ring·form·rivals)은 라우트에 남겨 둔다.
- 삽입 위치: 포스터=첫 섹션 앞, 덤벨=선정 이유 끝, 피자=이번 달의 전술 끝, 순위 흐름=결정적 경기 끝, 선수 카드형=글 끝. 섹션 제목이 다르면 글 끝으로.
- 카드 주소에 글 번호가 들어가 글 저장 뒤에 삽입한다. 백필은 라우트 배포 뒤에 해야 깨진 이미지가 안 보인다.
- 2026-09-29 경기 전술 글에도 카드. 입구 `?match=<경기 번호>&side=home|away`. 감독은 ts 라인업 `coach_id` → `coach-photos.json`.
- 경기 글의 집계 상한은 **그 경기 시작 시각**(포함)이다. 월말로 잡으면 글 발행 뒤 치른 경기가 섞여 본문과 어긋난다.
- 경기 글은 감독이 둘이라 포스터·피자·선수 카드형은 양 팀 짝(`pair=1`, 넓은 화면에서 나란히), 순위 흐름·덤벨은 양 팀을 함께 강조한 한 장. 총 8장.
- 양 팀 중 한쪽이라도 감독·기록이 안 잡히면 카드를 아예 넣지 않는다(`matchCardWho`). 폴백 그림이 본문에 박히는 것을 막는다.
- 월간 기록(monthRecord·form)을 글에 저장된 값 대신 DB 경기에서 계산하도록 바꿨다. 월간 글 포스터가 변경 전과 바이트 단위로 같음을 확인했다.
- 피자 차트 백분위 칸은 값이 낮으면 가운데 사진을 덮어 최소 반지름을 뒀다.
