# 농구 블라인드 드래프트 — 컨텍스트 노트

작성 2026-09-27. 결정과 근거를 계속 덧붙인다.

## SixRings 실측 (databallr.com/sixrings/laker, 2026-09-27)

- 판 1개 = 한 구단 21장, 픽마다 구단이 바뀐다 (BKN → OKC → NYK → PHX → DET).
  구단은 계보 단위다 (OKC 판에 시애틀 시절 게리 페이튼이 나옴).
- 픽 직후 판 전체 공개 + 기여도 순 정렬 + 내 픽 등수. 이게 재미의 핵심.
- 수치 규모. 주전급 +1~3, 역대급 +9~10. 완주 결과 +19.8 이 하위 13%, 당일 1위 +52.8.
- 보너스. 풀 라인업 +3, 균형 -2~+2, 내구성 -1.5~+1.5, 락다운(수비 합 +11 초과) +4.
- 찬스. Redeal, Swap Teams, Position(10~15장), Double Dip, Reveal, Flashbang, Spyglass 3회.
- 비회원 플레이 가능, 결과마다 고유 URL(`?r=uuid`), 오늘 Top 20·역대 리더보드.
- 그쪽 지표(LAKER·DARKO)는 고유 자산이라 쓸 수 없다. 우리는 박스스코어로 자체 산출.

## 데이터 실측

- NBA. ESPN `statistics/byathlete?season=YYYY&limit=800` 가 **1994 시즌부터** 전 선수를 준다
  (1994 402명, 1992 14명, 1990 0명). 필드는 경기·분·득점·야투·3점·자유투·리바운드(합계만)·
  어시스트·턴오버·스틸·블록·파울. 공격/수비 리바운드 구분 없음.
- NBA 포지션은 거칠다. 2026 시즌은 G 272·F 217·C 85 로 PG/SG 구분이 거의 없다.
- NBA 사진은 옛 시즌에 거의 없다 (1996 시즌 402명 중 13명). 실루엣 폴백 필수.
- KBL. `api-stats.kbl.or.kr/.../traditional?seasonCode=N` 이 **시즌 코드 1(1997)부터** 나온다.
  한글 이름 포함, oR/dR/tO/foul 까지 있음. Origin/Referer 헤더가 없으면 401.
  listCn 은 120 까지 (128 이상이면 서버 500).
- KBL 시즌 목록은 31개 (코드 1~49, 중간에 빈 번호 있음).
- KBL 팀 코드는 구단명이 바뀌면 달라질 수 있다 → 계보 매핑 필요.
- KBL 사진은 `kbl.or.kr/files/kbl/players-photo/{playerNo}.png` 가 옛 선수도 200.
- 우리 DB 에는 선수-시즌 저장분이 없다 (LeagueLeader 는 상위 10명·1시즌).

## 결정과 근거

- **슬롯은 가드 2·포워드 2·센터 1.** SixRings 의 PG/SG/SF/PF/C 를 못 따라가는 이유는
  원천 포지션이 G/F/C 수준이라서다. 두 리그 규칙을 같게 맞춘다.
- **수치는 서버에만 둔다.** `/career` 처럼 클라이언트 100% 로 하면 풀 JSON 이 통째로
  내려가 개발자 도구로 답이 보인다. 리더보드가 있으므로 판 생성·공개를 서버가 한다.
- **진행 상태는 DB 에 저장.** 서명 토큰만 쓰는 무상태 방식은 같은 판에서 여러 카드를
  찔러보는 재시도를 못 막는다.
- **User 테이블과 FK 를 걸지 않는다.** 새 테이블만 만들면 기존 테이블에 락이 안 걸린다
  (2026-07-04 prod DDL 락 사고 교훈). userId 는 문자열로만 보관.
- **풀은 빌드 타임 JSON.** 런타임에 ESPN·KBL 을 부르지 않는다.
- **기여도는 시즌 내 표준화.** KBL 초창기 외국인 선수는 평균 33점이라 원시값을 쓰면
  시대 간 비교가 깨진다.
- **WKBL 제외.** 리그 전체 시즌 표가 없고 선수별 통산 조회뿐.
- 작업 브랜치는 origin/main 보다 625커밋 뒤였고 로컬 main 은 origin 과 갈라져 있었다.
  브랜치에 고유 커밋이 없어 `git reset --hard origin/main` 으로 맞췄다.

## 구현 중 결정 (2026-09-27)

- **기여도 산식.** 공격 = 득점 + 0.4·야투성공 − 0.7·야투시도 − 0.4·(자유투 실패) + 0.7·어시스트 − 턴오버
  + 0.7·공격리바운드. 수비 = 스틸 + 0.7·블록 + 0.3·수비리바운드 − 0.4·파울. 모두 경기당 평균.
  시즌 내 규정 선수(최다 출전의 40% 이상, 평균 15분 이상)로 z 점수를 내고 공격 ×2.2, 수비 ×1.3.
  결과 상위는 요키치 '25, 데이비드 로빈슨 '94, 르브론 '10, 수비는 벤 월리스 '02~'04.
- **NBA 리바운드.** ESPN 이 공격/수비를 안 나눠 줘서 25:75 로 가른다. KBL 은 실제 값.
- **평균 이하 시즌은 카드에서 제외** (공격+수비 < 0). 첫 시험 판에서 무명 선수가 너무 많아
  아무나 뽑으면 -3 이 나왔다. SixRings 도 판의 최저가 +0.0 이다.
  제외 후 NBA 3,820장·KBL 906장, 구단별 선수 최소 36명.
- **슬롯은 뽑을 때 고르지 않는다.** 아무 카드나 뽑고, 서버가 가장 많이 채워지는 배치를 찾는다.
  막힌 판(들어갈 자리가 없는 판)이 생기지 않는다.
- **철벽 수비 기준과 백분위는 모의 1만 판에서 나온다** (`baseline.ts`). 모의 플레이어는 찬스 없이
  득점 위주로 고른다. 철벽 기준 = 수비 합 90백분위 (NBA 12.2, KBL 11.0).
  반지 구간은 10·28·45·62·78·90 백분위. **실제 플레이가 쌓이면 DB 분포로 재보정할 것.**
- **KBL 구단 계보.** 나래·삼보·TG → DB, SBS → 정관장, 대전현대 → KCC, 나산·골드뱅크·코리아텐더·KTF → KT,
  대우·신세기·인천SK·전자랜드 → 한국가스공사, 오리온·캐롯 → 소노.
- **KBL 포지션은 프로필 API** (`players/profile/0/{playerNo}`) 1콜. 규정 충족 646명만 조회.
- **NBA 옛 선수 이름.** 공용 사전에 없는 1,283명을 Haiku 로 음역해 `data/draft-names-nba.json` 에 따로 둔다.
  공용 `nba-player-names-haiku.json` 은 주간 봇이 다시 쓰고 사이트 전체에 영향을 줘서 분리했다.
- **KBL 사진.** 없는 선수는 200 + HTML 이 와서 img 오류 → 실루엣 폴백으로 처리된다.
- **테이블 생성.** `prisma/sql/create-draft-game.sql` 을 사용자 확인 후 실행. 첫 시도는 Neon 연결 실패,
  재시도에서 성공. `tsc` 는 메모리 부족으로 죽으니 `npm run typecheck` (8GB) 로 돌린다.
- **검증 결과.** 단위 테스트 9건 통과, typecheck·eslint 통과. 로컬에서 NBA 한 판 완주
  (돋보기·전체 공개·더블 픽·포지션·시즌 섞기), 결과 페이지·OG 카드·이어하기·375px·라이트/다크 확인.
  API 응답의 미공개 카드 키는 id·name·season·teamName·pos·photo·picked 뿐.
- 시험 플레이로 DraftGame 에 비회원 행 3건이 남아 있다 (리더보드에는 회원만 나오므로 노출 없음).

## 게시판 올리기·기준선 재보정 (2026-09-27 배포 직후)

- **게시판에 올리기.** 결과 화면 버튼 → `/community/new?draft={id}`. 전술판·승부예측과 같은 프리필 방식이라
  Post 테이블에 컬럼을 추가하지 않았다(prod ALTER 회피). 본문은 공유 카드 이미지 + 라인업 표 + 보너스 + 링크.
  수치는 `buildDraftShareText` 가 DB 에서 다시 읽는다 (`src/lib/draft/share.ts`).
- **기준선이 너무 셌다.** 첫 실사용 판(요키치 + 풀 라인업, +23.2점)이 하위 1%·반지 없음으로 나왔다.
  모의 플레이어를 NOISE 4·FIT 1.0 → NOISE 16·FIT 0.7 로 낮춰 NBA 중앙값 36.6 → 24.2, 6반지 기준 46 → 33 부근.
  같은 판이 백분위 44·반지 2개가 됐다. 철벽 기준도 NBA 12.2 → 9.8 로 내려갔다.
- **백분위·반지는 읽을 때 계산한다.** 저장값(DraftGame.percentile·rings)은 끝난 시점 기준이라 재보정이 반영되지 않는다.
  `service.ts standing()` 이 total 과 현재 quantiles 로 다시 낸다. 저장 컬럼은 남겨 두었다.
- 백분위 표기는 항상 "상위 N%".
