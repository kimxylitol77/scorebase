# /lab 조건식 시스템 빌더 — 컨텍스트 노트

## 결정
- **손잡이 봇과 별개 빌더**로 둔다. 손잡이 봇은 "어떻게 계산할까", 조건식은 "어떤 경기만 고를까". 같은 페이지 회원 구역에 두 번째 카드로 배치.
- **1단계는 저장 없음.** MemberBot 스키마(knobs Json) 변경 없이 빌더·백테스트·예정 경기만 연다. 2단계에서 knobs 에 `{ kind: "rules", ... }` 를 실어 봇의 한 종류로 저장하면 매일 픽 cron·/picks 랭킹이 그대로 따라온다.
- **픽 방향은 1X2 만**(HOME/DRAW/AWAY). 오버언더는 총점 기준선이 경기마다 달라 1단계 제외.
- **조건 재료는 DB 에 이미 있는 것만**: 마감 배당(oddsHome/Draw/Away, 마진 포함), 모델 승률(pred*), 시장 승률(market*), 오픈 대비 시장 변동(openingMarket* 대비), 팀 최근 5경기 승률·경기당 득점·실점·연승연패·휴식일(리그 히스토리 시간순 단일 스캔으로 as-of 산출). xG 는 빅5 축구만 있어 제외.
- **표본 가드** 20경기 미만은 "표본 부족" 으로 결과 카드 자체를 회색 처리. 우연한 90% 가 퍼지는 걸 막는 게 목적.
- **기준선** 같은 부분집합에서 우리 모델 픽(predCorrect) 적중률을 나란히 보여준다 — "조건이 모델보다 나은가" 가 질문이라서.
- 피처 API 는 bot-backtest 와 같은 형태(리그별 튜플 배열, rate limit 10/분). 히스토리는 since−60일부터만 읽어 폼 계산 재료를 확보.

## 경기 링크 규칙
- 야구(KBO/NPB/MLB)는 `/live/{league}/{externalId}`(숫자만), 나머지는 `/live/{league 소문자}/{Match.id}` (LiveScoresBar·OddsFlowList 관례).

## 실측 (dev, 2026-09-15)
- API 처리 85초 중 DB 두 쿼리가 54초(맥 회선), 피처 계산은 34ms. 프로덕션의 같은 형태 API(bot-backtest)는 17초라 60초 제한 안이지만 무겁다 — 2단계에서 페이로드 캐시(파일 또는 KV) 검토.
- 프리셋 "기세 탄 원정 언더독": 1,502경기 34% · ROI −7.8% · 같은 경기 모델 53%. "모델이 시장보다 홈을 높게 5%p": 1,484경기 37% · −8.6% · 모델 54%. 조건식이 모델을 못 이기는 게 기본값 — 그래서 기준선을 나란히 둔다.
