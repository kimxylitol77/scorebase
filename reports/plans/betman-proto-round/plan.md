# 베트맨 프로토 강화 1차 — 회차 아카이브·결과·AI 적중·배당 변동

2026-09-21. 경쟁 실측(와이즈토토·정배당·픽센터) 대비 우리 /odds 베트맨 탭의 공백 세 가지를 한 묶음으로 메운다.
근거와 실측은 `context-notes.md`, 진행은 `checklist.md`.

## 무엇을

1. **회차 아카이브** — `/odds?sport=betman&round=260111`. 회차 선택 바(최근 10회차 + 발매중), 지난 회차의 전 경기를
   현재와 같은 카드로 보되 **결과 칩**(홈승·무·원정승 / 핸디 승패 / 언더·오버 / 홀·짝 / 적특)과 스코어를 붙인다.
2. **AI 적중 도장** — 기본형(승무패·승패) 카드에 우리 1X2 픽과 베트맨 공식 판정 대조 결과. 예정 경기는 "AI 픽 홈/무/원정" 칩.
3. **회차별 AI 성적표** — 회차 단위 적중률(전체·종목별), 적특·미판정 제외. 베트맨 탭 상단 카드에 최근 회차 막대.
4. **배당 변동 화살표** — 베트맨 응답의 `tooltipList`(회차 시작 이후 전 변경 이력, 변경 전/후 배당·핸디)를 새 테이블에
   쌓고, 배당 옆에 ▲▼ + 이전 값. 워커는 필드 하나만 더 보낸다.
5. **버그 수정** — 언더오버 라벨이 뒤집혀 있었다(`winAllot`=언더, `loseAllot`=오버가 정본). 같은 파일을 만지는 김에 고친다.

## 왜 이 순서

- 재료가 이미 DB 에 있다(12회차 결과 100%, 경기 연결 90%). 화면과 집계만 붙이면 와이즈토토 회차 화면과 같은 급이 된다.
- AI 적중 도장·회차 성적표는 경쟁 셋 중 픽센터만 갖고 있고, 우리 픽은 선발·골리·시장 블렌드가 들어가 있어 근거가 다르다.
- 배당 변동은 세 경쟁이 다 있고 우리만 없던 항목. 베트맨이 이력을 통째로 주므로 자체 스냅샷을 만들 이유가 없다.

## 하지 않는 것

- 핸디·언더오버 AI 적중 — 우리 라인과 베트맨 라인이 달라 픽 방향만 옮겨 채점하면 공정하지 않다. 후속.
- 유사 과거 경기 검색 — 아카이브 6주. 연말 재검토([[betman-link-and-margin]] 유지).
- 기록식·토토(승무패/스페셜/매치) 게임 — 별도 gmId, 범위 밖.
- 도박 프레임 문구·조합 추천. 미디어 프레임 유지.

## 검증 기준

- `npm test` 에 결과 코드 매핑·회차 집계 순수 함수 테스트 통과.
- `npm run typecheck` + `npx eslint` 통과.
- 운영 DB 로 회차 260111 렌더: 결과 칩·스코어·AI 도장이 SQL 프로토타입 수치(축구 57/123, 야구 48/88)와 일치.
- 워커 배포 후 다음 정기 실행에서 `BetmanOddsChange` 행 유입 + 화면에 ▲▼.
