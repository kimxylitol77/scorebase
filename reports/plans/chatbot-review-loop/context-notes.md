# 챗봇 자동 점검 루프 — 컨텍스트 노트

## 출발점 (2026-09-29)

사용자 "챗봇 어떻게 하면 똑똑해지고 자동 업데이트? 매일 내가 체크해야 해?" → 제안 1~3(자동 채점·요약 알림·승인형 규칙) 승인.
챗봇(src/app/api/chat, src/lib/chatbot)은 사용자 영역 — 이번 범위는 사용자 승인 건.

## 실측 (최근 14일)

- 170건 / 47 IP, 하루 2~34건. 되묻기·못 답함이 약 19%(33건).
- 반복 실패: 넓은 질문("오늘 경기", "신뢰도 높은 예측")에 리그를 되물음(9/20 규칙 추가 후에도), "99배" 고배당 조합 요청 4회(도구 없음).
- ChatLog 는 question·answer·ip 만 — 도구 호출·만족도 없음(이번 범위 밖, 제안 5번).

## 결정

- 완전 자동 규칙 반영은 하지 않는다 — 사용자 질문이 곧 학습 재료라 악의적 반복으로 프롬프트가 오염될 수 있다. 제안은 PROPOSED, 관리자 승인 시 ACTIVE.
- 규칙은 행동 지침만(사실·숫자 금지), 200자 이하, 하루 최대 3개 제안. 기존 규칙을 채점기에 보여 중복 방지.
- 규칙 블록은 기본 프롬프트(ephemeral 캐시)와 별도 블록 — 규칙이 바뀌어도 기본 캐시가 안 깨진다.
- 텔레그램은 기존 sendTelegram(운영 cron 다수 사용). 요약 한 통, 실패·새 제안이 없으면 짧게.
- DB 사실 대조(경기·시각·확률)는 v1 범위에서 제외 — 답변 속 경기 식별이 불안정해 오탐이 많다. 채점기는 "근거 없이 단정한 수치" 같은 의심만 표시.
- 스케줄 09:00 KST(00:00 UTC) — 전날 KST 하루분.
